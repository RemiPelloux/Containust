# Changelog

All notable changes to Containust are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Compatibility guarantees for `.ctst`, `state.json`, and the SDK are described in
[`docs/VERSIONING.md`](docs/VERSIONING.md).

## [Unreleased]

### Added

- **Zero-downtime updates.** `update = "start-first"` makes `ctst run` start
  the replacement as `<name>~next`, wait for its healthcheck, switch the
  published ports to it atomically, drain the old container for `stop_grace`
  (default `2s`), then remove it and rename the new one. An unhealthy
  replacement is discarded and the old container keeps serving; leftovers
  from an interrupted update are removed by the next `ctst run`.
- `.ctst` properties `update` (`recreate` | `start-first`) and `stop_grace`.
  `start-first` requires a `healthcheck`. Neither is part of the spec
  fingerprint, so changing them alone does not replace a container.
- `ctst plan` tags start-first replacements (`[start-first]`, JSON
  `"strategy"`) and prints a `note:` when start-first falls back to
  `recreate` (host network, shared network, VM backend).
- Runtime/SDK: `ContainerBackend::{supports_handoff, handoff, rename}`,
  `ContainerConfig::defer_publish`, `supervise::wait_healthy`,
  `UpdateStrategy` in `containust-common`.

### Fixed

- Port forwarders: per-connection helpers no longer keep the listening
  socket open, so a stopped forwarder frees its host port immediately, and
  finished helpers are reaped instead of lingering as zombies.
- Removing a container now unmounts and deletes its persisted network
  namespace (`.containust/networks/<id>/ns`).
- Docs: `network` defaults to `"none"` (private namespace), not `"bridge"`.

- Release: the packaging-bump job now checks out `main` and passes
  `base: main`, so the Homebrew/winget PR opens from a tag-triggered run
  (it previously stopped at "the 'base' input must be supplied").

## [1.3.1] — 2026-10-15

### Added

- **`ctst download`**: one connected run prefetches everything needed for
  air-gapped / on-prem use: pinned VM boot assets (`--vm auto|always|never`),
  composition images, curated presets (`--all-presets`), and registry images
  (`--image`, repeatable). It then reports whether the composition is ready for
  `ctst --offline`. Supports `--dry-run`.
- Runtime: `backend::vm::prefetch_boot_assets()` and `backend::vm::vm_cache_dir()`.

### Fixed

- `ctst download --dry-run` no longer reports a composition as "offline ready"
  before anything has been downloaded.
- Release: the Homebrew/winget packaging-bump job failed on `1.2.0` and `1.3.0`
  because the Windows checksum is written with CRLF line endings. The bump
  script now strips `\r`, and a blocked bump PR no longer fails the release run
  (the job summary links to the pushed branch instead).

### Documentation

- `ctst doctor` and `ctst download` documented in the CLI reference, the
  operator guide, and the docs site; the air-gapped workflow uses
  `ctst download`.

## [1.3.0] — 2026-10-15

### Added

- **Declarative plan/apply.** `ctst plan` now diffs the `.ctst` file against
  live containers and a per-project applied-spec ledger
  (`.containust/state/applied.json`): `+ create`, `~ replace`, `> start`,
  `= keep`, `- remove`. Each component is fingerprinted (SHA-256 over image,
  command, env incl. `CONNECT` wiring, limits, volumes, ports, network,
  restart, healthcheck, namespace policy).
- `ctst plan --json` (machine-readable plan) and `--detailed-exitcode`
  (exit `2` when changes are pending — CI drift checks).
- **Idempotent `ctst run`.** Re-running an unchanged file is a no-op; stopped
  components are started; changed components are replaced one at a time in
  dependency order, cascading to dependents of a replaced upstream.
  `ctst run --prune` stops and removes containers no longer declared.
- SDK/runtime: `Engine::plan`, `Engine::apply(ApplyOptions)`,
  `containust_runtime::plan` (`DeployPlan`, `PlanAction`, `Ledger`).
- Animated README (hero, terminal demo, architecture) generated by
  `scripts/gen_readme_assets.py`; use-case guide in the README.

### Changed

- `ctst plan` is read-only: it no longer creates project state on a fresh
  project.

### Fixed

- Re-running `ctst run` on a deployed project failed with
  `container name already exists`; it now reconciles instead.

### Performance

- **Stop:** graceful stop polls for exit every 20 ms instead of always
  sleeping 2 s, and signals/waits outside the exclusive state lock
  (`ctst stop` / Ctrl+C on N containers no longer costs N × 2 s).
- **Create:** rootfs copy/extract/materialize runs outside the exclusive
  state lock in `rootfs-staging/` and is renamed into place on commit, so
  concurrent `ctst ps`/`stop`/`exec` are not blocked by large images.
- **Pull:** `ctst pull` reuses layers already in the content-addressed store
  instead of re-downloading them.
- **Extract/pack:** 256 KiB buffered tar read/write path with a single open;
  fewer `stat` calls per entry when packing.
- Whiteout pass no longer follows symlinked directories (also fixes a
  potential loop on self-referencing symlinks).
- State saves serialize a borrowed view instead of cloning every entry;
  `ctst logs` tolerates non-UTF-8 output.
- New perf gates: stop latency and 10k-small-file extraction
  (`docs/PERFORMANCE.md`).

### Maintenance

- Security: rustls 0.23.46 (RUSTSEC-2026-0285); YAML parsing for `ctst convert`
  moves from the archived `serde_yaml` to the maintained `serde_norway` fork
  (RUSTSEC-2024-0449, unmaintained `unsafe-libyaml`).
- Dependency refresh: all crates updated to their latest MSRV-compatible
  releases (115 lockfile updates); major bumps `sha2` 0.11, `which` 8,
  `aya` 0.14 (drops the `thiserror` 1.x duplicate). Workspace resolver 3 keeps
  future `cargo update` runs MSRV-aware. `reqwest` stays on 0.12.28: 0.13
  switches TLS to aws-lc-rs plus OS trust stores, which needs its own review
  for air-gapped hosts and cross builds. `cargo audit` / `cargo deny` clean.
- Clean `clippy -D warnings` on Rust 1.99 stable (`assert_is_empty`,
  `thiserror` 2.0.21); MSRV stays 1.88.

## [1.1.0] — 2026-07-23

### Added

- **OCI registry pull** (`ctst pull`, `oci://` scheme): manifest index →
  platform manifest → digest-verified layer blobs, imported into the local
  content-addressed catalog as `image://name@sha256:...`. Digest pin required
  by default; `--offline` rejects registries before connecting.
- Registry auth via `CONTAINUST_REGISTRY_TOKEN`, `CONTAINUST_REGISTRY_USER`/`_PASSWORD`,
  or `~/.docker/config.json`; credentials never logged or persisted.
- **`EXPOSE` statement** parsed per the documented grammar; identity port
  publishing enforced (Linux host-network publish, VM multi-`hostfwd`).
  Host/container remapping fails closed with an actionable error.
- **Restart policies** (`never` / `on-failure` / `always`) and **healthchecks**
  enforced daemonlessly on every reconciliation pass (`ctst ps` / `ctst run`).
- Privileged Linux CI job running the root-only namespace/cgroup/mount fixtures.
- Packaging: in-tree Homebrew formula, `.deb`/`.rpm` via nfpm in the release
  workflow, winget manifest template, cosign-signed `SHA256SUMS`.

### Changed

- State schema bumped to 3 (`ports`, `restart`, `healthcheck`, `health`,
  `restart_count` on container entries); older states migrate automatically.
- Preset hints for uncurated images now point at `ctst pull`.

### Fixed

- `CgroupManager::destroy` used `remove_dir_all`, which cgroupfs rejects;
  now uses plain `rmdir`. Controllers (`cpu`, `memory`, `io`) are enabled in
  the parent cgroup's `subtree_control` on create.
- User-namespace test fixtures fork a single-threaded child so
  `unshare(CLONE_NEWUSER)` can succeed under the test harness.
- `examples/alpine_preset.ctst` used unsupported `#` comments.
